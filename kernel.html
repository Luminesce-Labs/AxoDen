AxoDen Kernel Shared control core

A control core for evidence and recorded decisions.

AxoDen platform · developed at axoden.io

The shared kernel implements evidence identity, ordered decision gates, session-bound checks, configurable domain profiles, append-only records and replay mechanisms for inspecting recorded decisions.

Dossier Intelligence Research basis

What the kernel implements

These are reusable contracts. Domain applications supply ingestion, domain logic, interfaces and human review.

Evidence identity

Evidence objects have a stable identity before they are used downstream.

Ordered decision gates

Checks run in a declared order before an outcome is recorded.

Session-bound checks

A check is bound to the session in which the decision is made.

Domain profiles

The same control core can load a profile for a specific domain.

Append-only records

Recorded outcomes accumulate. They are available for later inspection.

Replay

A recorded decision can be inspected again from the record.

Coverage, stated narrowly

The software architecture shows where broader mathematical operators and verification contracts can enter. The current kernel covers a narrower set.

Attestation-record verification, Goodhart detection and the full research operator set sit outside the current kernel. The Attested Epistemic Integrity Plane specifies the composed assurance architecture. Implementation and deployment validation of that complete runtime plane remain outstanding.

The graph layer represents provenance, support, contradiction and dependency through domain schemas and queries. How far the same runtime is reused across domains still needs evaluation.

Where it is used now

  • Dossier Intelligence supplies versioned Neo4j projections alongside its evidence and audit backend.
  • Forensic intelligence uses selected controls on admission and recorded outcomes.
  • Spectrum Bridge uses admission, refusal, an append-only ledger and session-bound checks inside its recorded scope.

Roles, kept separate

APASES is the research environment. The research documents specify concepts and results. The kernel enforces selected controls. Domain applications supply operational workflows.

Keeping those roles separate means a research method, a proof claim and a software capability can each be examined on their own evidence.
